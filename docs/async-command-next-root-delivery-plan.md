# 异步命令完成投递与观察优化

## 范围

在最新 main 的独立工作树中实现并提交一个 PR，版本保持 1.1.9。复用现有 TerminalFuture、TerminalSettlement、command.completed 和 MCP 最终响应适配器，覆盖 Windows、Linux、macOS 及 Android Core。其他开放 PR 和工作树保持独立，提交前复核最新 main 的集成差异。

## 实现顺序

1. 增加有界、原子持久化的完成投递账本，使用原始命令调用标识去重，保存来源对话、任务、工作区与已持久化终态引用。
2. 只在同一可信所有者和对话的后续外部根调用返回时领取完成事件。根调用、内部子调用、UI 查询和用户插入各自保持原有身份语义。
3. 将 command_completions 作为适配器私有事实附带到 agentdock_guidance；保留业务错误、图片、资源和用户 response_additions，保护外层投影，提供紧凑文本兼容块。
4. 取消 running 结果中的强制观察，保留按依赖等待的 continuation。auto 默认等待10秒，status 自适应5/15/60秒，显式等待上限300秒，并让请求取消只取消等待者。
5. 以独立 origin_call_id 关联命令观察。仅默认折叠有可见原命令、无错误且无输出缺口的观察，保留根调用计数、原始审计和详情展开；输入、停止及错误独立显示。
6. 补充隔离、并发领取、直接观察去重、编码失败、外层投影、重启恢复、资源上限、取消等待和 UI 回归，执行全仓与跨平台验证后提交一个 PR。

## 投递语义

每个逻辑完成事件稳定去重，普通客户端采用至多一次附带：pending → reserved → appended。编码前失败释放领取；已构造响应后外层投递失败记为 delivery_unknown，不自动重新执行命令或重复投递。appended 表示已加入响应，不表示宿主模型已确认接收。崩溃时仅回收已死亡进程持有的未提交领取，已提交事件保持去重。未来的宿主上下文确认可另行协商，本 PR 不增加确认工具或主动唤醒。

每批最多8项，结构化数据与文本兼容块合计受8 KiB预算约束。账本仅保存固定终态摘要和活动标识，不复制命令文本、环境或完整输出。每对话最多64个待投递事件，全局记录及文件大小有硬上限，保存24小时。容量错误保留原始活动事实并记录诊断，不改变命令结果。

直接 session_observe/session_act 已在响应中报告同一会话终态时，仅登记消费，不重复附带。当前任务切换不改变事件的原始归属；对话删除、终止或失去所有权时停止投递。取消观察不等于取消命令。没有后续根调用时，UI 仍由现有命令活动更新，事件保持待投递直到保留期结束。

## 验收

- 一个异步命令产生一个逻辑完成事件，后续根调用收到一次，其他所有者、对话及内部调用收不到。
- 并发根调用不会同时领取同一事件；重启、重复编码和投影保持稳定事件标识及消费状态。
- 成功、非零退出、超时、终止、未知结果准确保留，未保存的终态不伪装成成功。
- 终态附带不消费 stdout/stderr 游标，不捏造指向最终日志的引用。
- 当前业务工具失败仍可携带此前命令终态，原 isError 与非文本内容保持不变。
- 有独立工作时不要求轮询；必须等待时提前响应终态及调用取消，支持多个互不干扰的观察者。
- UI 折叠只改变展示，查询、导出、审计、原始根调用统计和异常可见性保持有效。
