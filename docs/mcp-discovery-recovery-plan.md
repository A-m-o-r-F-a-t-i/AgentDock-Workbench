# MCP 发现路由修复计划

## 范围与证据

本次基于 main 29e2f4ea，用户记录包含 2390 个唯一 call_id，其中 571 次 mcp_tool_search，412 次为未指定服务的精确 mcp_tool_call 查询。记录由服务端观察，不能据此确认外部宿主当时实际注入了哪些 Schema。1.1.9 已增加成功交接提示，仍缺少重复误路由分类和针对该错误的恢复提示。

## 实施

- [x] P0：无服务范围的内置名称及明确别名返回 HOST_BUILTIN_NOT_DYNAMIC_MCP、retryable=false 和规范宿主工具引用。纯内置 inspect 使用相同规则，混合 inspect 保留独立动态结果及逐项错误。指定动态服务和 server:tool 保持原语义。
- [x] P0：按可信接入层 owner/conversation/workspace/binding revision 和规范工具名，识别短窗口内重复误路由并返回 ROUTING_LOOP_BLOCKED。状态有容量和时限，支持并发，无身份请求不共享状态，不影响正常业务调用。
- [x] P0：错误恢复引导指向宿主工具命名空间，禁止再走动态 search/inspect；不伪造执行参数、宿主 Schema 已加载或命令已执行。真实请求仍各自记录为失败，不能隐藏请求来降低数量。
- [x] P1：统一工具描述与 plugin_load 的已有目录复用说明。保留上下文丢失后合法 list/inspect 重读，不设置每会话永久一次的门禁。
- [x] 定向回归：内置首次误用、连续十次重复、别名与 limit 变动、跨入口重复、并发会话、无任务、无身份、绑定变更、到期/容量、混合结果、动态同名工具、认证错误、宿主 tools/list 可见性、错误提示和正常多次调用恢复。
- [ ] 交付：Go/Windows 全量回归、PR 审查、合并精确提交，使用现有全平台工作流发布 v1.1.10 预发布并验证八项公开资产；保留 v1.1.9 和稳定 Latest，不操作其他 PR、不替换生产 Core。

## 验收边界

服务端负责拒绝错误路线和暴露可执行宿主引用，外部宿主负责真正加载 Schema。错误码无法强制外部模型停止发送请求。协议重放与集成测试单独报告，不标称为未经执行的真实模型 A/B 实验。状态断路仅针对内置工具误用，不锁定合法目录读取、参数修正或业务执行。保留认证、权限、用户插入和任务绑定机制。
