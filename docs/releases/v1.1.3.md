# AgentDock 1.1.3

　　相对 1.1.2，1.1.3 重新整理对话执行界面，补齐对话级终止与恢复、执行记录管理、标题与来源状态，并修复 Windows 覆盖升级和残留回滚事务。

## 1. 对话优先的执行界面

　　导航统一为“工作区 → 对话 → 对话内任务与执行记录”，减少任务模式和对话模式互相抢占层级。主区域移除重复标题和空白顶栏，权限、连接、主题、设置和对话操作集中到标题行。

　　工具调用改为紧凑单行，默认展示状态、动作名和耗时；窄窗口自动收缩非关键字段。调用详情按命令与输出、来源、子调用和技术信息组织，失败、待审批和未知结果不会默认撑开列表。

　　历史任务与未归属记录进入独立管理入口，不再混入普通对话侧栏。

## 2. 对话终止与恢复

　　“终止对话”会先持久化终止门禁，再拒绝待审批请求，并停止该对话中仍在运行的调用和异步命令。后续执行请求返回明确的已终止状态。

　　恢复只允许从本地管理入口发起，不会重新播放已经取消的旧请求。终止范围限定在目标对话，其他对话继续运行。

## 3. 命名、来源和旧数据

　　对话标题按手动名称、宿主标题、首个明确任务、操作名称、工作区与创建时间逐级回退，旧的用户自定义名称保持不变。

　　来源状态区分读取中、已解析、暂不可用、已删除和读取失败。已删除来源不会与短暂读取失败混淆。旧任务缺少步骤时显示“进度未记录”，但不影响调用和历史读取。

　　旧占位对话的首次命名改为复用注册表快照、共享任务名称缓存并批量提交，大量旧记录首次打开时不再逐条完整读写注册表。

## 4. 执行记录管理

- 原始调用 ID 和旧日志投影形成的稳定 ID 都可以管理。
- 支持导出、隔离、归档、回收站和永久删除。
- 运行中或待审批的调用拒绝删除。
- 永久删除使用持久化墓碑，日志重放和迟到子调用不会让记录重新出现。
- 对话删除保留来源墓碑，避免同一来源再次被识别后重新生成。
- 批量操作固定对象集合，重新选择后旧快照失效。

## 5. 连接与权限状态

　　客户端连接状态改为依据真实通过认证的 MCP 请求，区分已连接、最近已连接、已授权、需要重新授权和本次启动尚无记录。匿名发现和陌生无效请求不会把已确认连接降级成“需要授权”。

　　公网可达性与客户端授权分开显示。权限界面继续展示全局、工作区和对话的继承关系；完全权限仍受显式禁止规则约束。

## 6. Windows 安装、升级与回滚

　　安装器会识别失败事务的阶段、源版本和回滚状态。当旧版本实际上已经恢复并健康，但仍残留 `rollback_failed` 等状态时，安装脚本会核对 committed pointer 和旧版健康状态，再对绑定事务执行安全协调，然后重新读取状态继续升级。

　　安装失败仍优先保留原程序、版本指针、凭据和用户数据，不通过删除事务记录掩盖系统状态。
