# AgentDock 1.1.1

　　相对 1.1.0，1.1.1 重点整理公网访问配置、任务活动中心展示和 Tailscale/OAuth 接入检查，使“配置草稿、当前生效状态、网络可达和客户端授权”不再混为一体。

## 1. 公网访问配置

　　仅本机、Cloudflare Quick、Cloudflare Named 和 Tailscale 四种模式使用各自独立区域。固定域名表单只在选择对应模式时展开，Token 提示也只出现在需要凭据的位置。

　　所选配置草稿与当前生效配置分别展示。刷新或应用失败会保留域名和输入内容，只有配置成功后才清理临时凭据。并发应用、重复生成和同时启停会被阻止，配置版本变化后旧检查结果不能覆盖新状态。

## 2. 任务活动中心展示

　　概览页增加任务活动中心入口，并复用单实例窗口。任务按待处理、进行中和已结束分组，状态、步骤进度、下一动作和原因分块展示，内部 ID 移到技术详情。

　　已取消与已归档保持独立语义。取消任务不会默认停止仍在运行的命令，界面会继续显示对应运行记录；停止操作核对具体任务、线程和真实会话状态，不从旧事件推断命令仍在执行。

　　文件定位、当前差异、命令复制和停止入口放在对应记录旁。历史浏览可以暂停自动跟随，并随时返回最新位置。

## 3. Tailscale 与 OAuth 接入检查

　　`WWW-Authenticate` 按认证方案和参数解析，兼容合法空白、参数顺序和大小写，同时拒绝重复或歧义字段。

　　公网检查将网络、认证发现和客户端授权拆成不同阶段。匿名检查不会携带本地凭据或跟随重定向，错误会保留所在阶段、路径、状态或传输原因。

　　服务端自检覆盖 MCP 初始化、通知和工具目录，但“服务端可访问”不再被解释成“ChatGPT 客户端已经授权”。真实客户端仍需单独完成授权、工具扫描和重连。

## 4. 使用边界

　　本版继续使用 WPF 与 Go。任务批量管理、分层审批和更完整的对话/任务双视图在后续版本加入；1.1.1 主要解决现有入口的状态表达和接入检查准确性。
