# AgentDock 1.1.4

　　相对 1.1.3，1.1.4 重点收敛 Windows 桌面视觉状态、真实调用观测、文件编辑记录、MCP Apps 显示策略、Tailscale Funnel 等待行为和管理员后台启动。

## 1. Windows 桌面界面

　　按钮、菜单和选择控件在鼠标移开后仍保留默认边框和选中状态，不再依赖悬停判断当前模式。浅色、深色和跟随系统主题统一使用应用级动态资源。

　　执行记录提供紧凑和详细视图，显示真实工具名、对话/任务标签和真实状态。旧记录缺少耗时时显示“未记录”，不再渲染虚假的零耗时。

　　对话侧栏根据真实根工具请求显示活动标记；列表刷新、健康检查和后台探测不会续期，已终止对话不会继续显示为活跃。

## 2. 调用观测与文件编辑

　　每个外部请求只建立一个根调用，内部阶段和子调用继承不可变绑定。请求、RPC、处理器、等待和命令进程分别记录时间，未知值保持为空。

　　`file_edit` 的 replace、patch、add、delete 和 move 会记录动作、路径、dry-run、是否执行、是否改变、受影响文件、增删行以及有界 diff。Schema 参数失败也进入调用历史，但明确标记为未执行。

　　路径、预览和输出在持久化前执行脱敏与截断，多文件详情保持有界。

## 3. ChatGPT MCP Apps 显示开关

　　控制面板增加“提供 AgentDock 内嵌界面”开关。保存后 Core 立即采用新策略，不需要重启服务。

　　关闭后只停止发布 AgentDock UI 资源和工具 UI 绑定，工具列表、结构化结果、文件参数、认证、任务、插件和动态 MCP 继续可用。已经在宿主中渲染的历史卡片不会被远程删除。

## 4. Tailscale Funnel

　　将“本机映射已应用”和“公网已经可访问”拆成两个阶段。DNS 或边缘传播暂时超时不会触发整套破坏性回滚。

　　状态查询采用短时缓存，重复点击共享正在进行的请求；完全匹配的既有映射直接复用。停止和回滚只处理当前运行目录拥有的根映射，不调用全局 reset、down 或 logout。

## 5. 管理员后台启动

　　管理员计划任务改为启动稳定托盘 WinExe 的 `--run-core-task` 入口，再由稳定 Shim 转发到当前版本 Core。后台进程使用无控制台方式启动，避免登录或安装结束后出现黑框。

　　稳定入口、当前版本托盘和 Core 的父子链保持安装回滚与同一 Windows 用户校验，不放宽未提交版本的启动边界。

## 6. 兼容与迁移

　　本分支和上游官方版不是可共享默认状态目录的并装发行线。跨发行线切换时应先备份并使用匹配版本迁移已复核的文本配置；凭据、审批、执行日志和安装事务不应直接复制。
