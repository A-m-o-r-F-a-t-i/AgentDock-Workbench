# AgentDock Workbench 1.1.10

　　1.1.10 为预发布版本，相对 1.1.9 修复内置工具与动态 MCP 工具之间的误路由处理，改善重复发现后的恢复指引。

## 工具发现与恢复

　　将 `mcp_tool_call`、`exec_command`、`read_file` 等内置工具误送入动态 MCP 搜索或检查时，返回明确的非重试型路由错误，并指向调用方的 AgentDock 工具入口。宿主缺少工具定义时，应在宿主目录加载对应 Schema，随后继续原任务；动态搜索不会代替宿主加载或执行工具。

　　同一对话绑定内，短时间重复发现同一个内置工具会被标记为重复误路由。别名和搜索数量变化不会绕过这一识别。重复状态按会话隔离并有有效期，不会阻止正常业务调用，也不会永久限制上下文恢复后的目录和 Schema 重读。真实请求继续保留独立记录，错误状态和恢复指引与执行事实分别呈现。

　　混合检查同时包含内置与动态工具时，保留成功读取的动态工具定义，并逐项说明内置工具的正确入口。显式选择的动态服务及其同名工具保持原有认证、权限和调用规则。

　　插件展开后的说明优先引导复用已返回的工具目录，仅在缺少 Schema 或能力版本变化时读取相应定义，减少再次搜索同一目录。

## 安装包

| 平台 | 安装包 |
| --- | --- |
| Windows x64 | `AgentDockSetup-amd64.exe` |
| Windows ARM64 | `AgentDockSetup-arm64.exe` |
| macOS Intel / Apple Silicon | `AgentDock-macos-universal.dmg` |
| Debian / Ubuntu x64、ARM64 | 对应架构的 `.deb` |
| RPM 系 Linux x64、ARM64 | 对应架构的 `.rpm` |
| Android | `AgentDock-Workbench-1.1.10-Android-test-signed.apk` |

　　Android APK 使用测试签名，Android 节点仍依赖外部 Termux 与 Linux 环境。已有应用签名与安装包不同时无法直接覆盖安装，处理旧应用前应保存需要保留的数据。该版本保留预发布标记，不替代稳定版入口。
