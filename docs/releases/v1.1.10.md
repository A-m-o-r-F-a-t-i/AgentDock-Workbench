# AgentDock Workbench 1.1.10

　　1.1.10 在 1.1.9 的基础上减少 MCP 调用的重复上下文，改进工具定义复用、插件启动和 Context 续读，并修复 Windows 命令窗口与 macOS 活动详情的显示问题。

## MCP 结果与工具定义

　　正常成功的 MCP 调用向模型返回业务结果、必要的续读信息和错误状态。调用身份、采集来源、目录摘要及投影诊断保留在活动记录中，日常调用不再重复展开这些信息。错误、审批、目录变化和来源采集失败仍会保留下一步判断所需的事实。

　　长结果继续使用宿主返回的原始续读参数，业务结果内部的分页参数保持独立。续页保留原始调用的失败事实，不能因当前页成功读取而把上游失败改写为成功。图片、音频、资源和不等价的文本继续按既有规则交付；可以证明与结构化结果等价的 JSON 文本只保留一份。

　　同一受信会话已经读取的工具定义按服务器身份与 Schema 摘要复用。无关目录版本变化不会再次展开未变化的完整定义；再次检查仍返回当前说明、元数据和工具属性。调用前后的目录状态检查只读取轻量身份与状态，减少重复枚举工具定义的开销。

## Context 读取与插件启动

　　空参数 Context 请求始终从当前上下文入口开始，不再隐式推进此前未读完的快照。需要后续详情时，使用响应中明确返回的 cursor。并发请求和已交付修订的引用保持紧凑形式，同时保留工具数量、服务数量和目录修订等必要路由信息。

　　已有正式版本和内容摘要的插件在 Core 启动时先读取目录身份、清单及 MCP 元数据。完整内容摘要和运行副本一致性在所选 Skill 或 MCP 首次执行前校验，减少启动阶段重复读取大量插件文件的等待。

## Windows 与 macOS

　　Windows 命令的 tty 选项只控制标准输入是否保持打开，普通 PowerShell 命令继续通过隐藏窗口的管道执行路径运行，减少偶发弹出命令窗口的问题。原有进程停止、超时和命令输出处理继续保留。

　　macOS Workbench 对已经留存的请求和输出优先显示稳定来源及字节数，避免立即展开大型预览。技术详情显示调用状态、来源、计时和交付摘要，完整原始数据仍可通过复制或导出取得。
