# AgentDock Workbench 1.1.10

　　1.1.10 为预发布版本，相对 1.1.9 修复图片读取结果被 Base64 内容占据活动记录、已绑定任务切换工作区后无法续读既有输出，以及完整 Context 已复用后仍容易触发重复读取的问题。

## 图片读取与结果留存

　　`view_image` 继续通过标准 MCP 图片内容向支持原生媒体的客户端交付图像，但图片字节只在最终 MCP 传输边界编码。Base64 只存在于最终 MCP 图片传输对象中；业务结果、活动记录和可续读来源不再保存 `_mcp_image_base64` 或图片数据块，而是保存图片尺寸、摘要、有效期和签名资源链接。

　　图片处理恢复使用调用方请求的 `max_bytes`，上限仍为 2 MiB，不再为了模型附件预算把所有图片预先压缩到 256 KiB。最终图片不超过原生附件预算时，客户端收到图片，结构化结果同时提供资源链接；超过附件预算时，模型响应省略内联图片，并通过留存来源继续提供链接和元数据。完整来源留存同样只保存链接和元数据，不再把 Base64 复制进活动源。

## 工作区切换后的输出续读

　　同一认证调用方在同一对话或同一任务中切换工作区后，可以继续读取此前调用产生的不可变活动输出，不再被要求先切回原工作区。输出所有者、对话和任务仍需匹配；没有对话或任务归属的输出继续绑定原工作区，跨调用方和跨对话读取仍被拒绝。

　　这项修改避免读取旧图片或命令结果时触发 `OUTPUT_WORKSPACE_MISMATCH`，继而反复调用 `agentdock_context`、改变当前工作区并使后续相对路径失效。

## Context 复用

　　`agentdock_context` 返回完整 Context、`unchanged=true` 引用或共享引用后，会明确返回 `reuse_context` 动作，说明本轮上下文获取已经结束。调用方应继续当前任务，只有工具报告 Context 丢失、修订变化、规则变化或任务确实需要另一个工作区时才重新读取。

　　初始化说明同步收紧：详情只使用精确 `next_cursor` 按需读取；完整或未变化的 Context 不轮询；`force_refresh=true` 仅用于明确的 Context 丢失或失效。
