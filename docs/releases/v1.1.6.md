# AgentDock 1.1.6

　　相对 1.1.5，1.1.6 大幅优化 `agentdock_context` 与插件目录复用，补齐结构化插入、MCP 批量 Schema、真实调用参数与输出、文件编辑统计，并修复 Windows 安装事务和内置 Skill 产物。

## 1. 上下文性能与复用

　　插件、Skill 和 MCP 目录采用不可变快照与成员索引。相同输入的冷请求共享一次构建，热调用复用完整快照；Heavy 筛选在正文读取前完成，未选择的服务不会因为获取上下文而启动。

　　规则、Skill、插件和 MCP 目录按作用域分别失效。共享构建不混用请求身份、权限、任务绑定和用户插入。单个等待者取消不会中断其他等待者，最后等待者退出后才取消无用构建。

　　新增 `AGENTDOCK_CONTEXT_TIMEOUT_MS`，只约束上下文准备链。成功返回 `complete=true` 后，同一工作区普通调用直接复用上下文，不因后台命令观察或一次普通错误机械重复 bootstrap。

## 2. 插入消息与应用显示协议

　　用户补充同时进入 MCP 尾部文本块和顶层 `structuredContent.agentdock_guidance.response_additions`，两者共享同一个 `insertion_id`。SDK 和直接调用使用统一响应附加器，保留原业务对象、错误、图片、资源和目录摘要。

　　第三方结果中同名字段仍是普通业务数据，不能提升为可信插入。界面把 `attached` 表述为“已写入工具响应”，不据此声称模型已经收到或阅读。

　　TextOnly 和 App 模式使用同一呈现状态管理工具目录、结果元数据和资源；关闭 App 显示后不再发布新的模板引用。

## 3. 完整 MCP 摘要与批量 Schema

　　已知服务可以直接调用 `mcp_tool_list` 读取完整工具名称和一行描述。`mcp_tool_inspect` 支持多个精确名称、`service:*` 和跨服务批量选择，并保留完整输入/输出 Schema 与嵌套约束。

　　`mcp_tool_call` 的业务响应会附带对应服务的完整摘要，复用同一目录缓存。目录附加失败不会把已经成功的业务操作改写成失败，也不会诱发重复写入。

## 4. 活动中心真实调用记录

　　外部根调用在接受并绑定对话后立即进入活动中心，不必等待工具结束。详情分为调用与输出，保存脱敏后的真实参数、结构化结果和 MCP 内容块。

　　命令和动态 MCP 在执行期间持续更新。失败、取消和超时不会清空此前记录；图片和二进制只保存类型与引用。大结果使用有界预览和授权分段读取，明确显示当前字节范围、总量和保存状态。

　　总耗时使用统一来源。缺少 RPC、执行或等待分项时保持未知，不用零值代替。

## 5. 项目导航与工具栏

　　项目默认展示最近 120 秒内有有效活动或运行时确认仍在执行的对话。点击三角显示最近 5 条历史，再通过省略号逐步加载更多。历史使用冻结排序快照，实时新增单独合并，避免翻页重复或漏项。

　　增加“折叠全部项目”，同时保留当前内容、插入草稿和运行任务。任务中心增加“控制面板”入口，删除重复的连接、主题和更早按钮，并合并简洁/详细视图切换。

## 6. 文件编辑统计

　　活动中心显示真实注册工具名。根调用展示新增和删除行数，详情保存每个文件的动作和统计。数字来自同一次受版本保护的编辑事务，不从截断 diff 或当前仓库状态反推历史。

　　统计统一处理 UTF-8、中文、空文件、CRLF/LF、末尾无换行、移动和覆盖移动。预演显示拟议值，完整回滚显示已知零；连接中断或归属不明时保留未知。

## 7. 控制面板与上游整合

　　显示与主题移到运行配置顶部，旧路由继续兼容。分组框和输入控件使用共享主题资源，保持键盘焦点几何一致。

　　上游改动通过真实双父合并整合，保留本分支的任务、对话、插入、停止、权限、Heavy 和 Skill 版本模型，同时引入不冲突的源适配器、租约、路径安全和 Windows 诊断改进。

## 8. Windows 安装事务修复

　　安装器管理操作改为按当前活动指针选择实际 Core。试运行版本、回滚后的旧版本和提交后的新版本分别解析自己的代际目录，避免固定调用稳定启动器而误入自更新事务检查。

　　停止试运行版本、恢复文件和重启旧版本均使用当时的权威活动代际，不提前提交版本，也不伪造更新事务。

## 9. 内置 Skill 产物

　　内置 Skill Bundle 清单补齐版本字段，名称、版本、包路径和摘要与运行时 Bootstrap 契约保持一致。缺失、空白或无效版本在构建产物生成前直接失败，不推迟到用户安装时处理。
