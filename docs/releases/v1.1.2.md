# AgentDock 1.1.2

　　相对 1.1.1，1.1.2 将任务活动中心扩展为“对话 / 任务”双视图执行中心，建立 Conversation、Task、Call 和 Session 的统一归属，并加入记录管理、批量操作、回收站和新的权限审批模式。

## 1. 对话与任务双视图

　　执行中心可以按对话或任务查看工具调用。没有任务绑定的读取、搜索和命令也会记录，不再因为缺少 Task 而从历史中消失。

　　对话身份由接入层解析，业务工具不需要模型逐次填写 `conversation_id`。任务绑定从当前对话状态继承，切换任务或分支不会改写已经开始的调用。

## 2. Call 聚合与执行记录

　　一次业务调用以单个 Call 聚合 started、output 和 completed，内部阶段保留父子关系。命令 Session 与工具 Call 使用不同生命周期，运行状态、输出、退出码和错误不会被多个内部事件重复计算。

　　支持任务里程碑、搜索、右键操作和批量管理。调用可以归档、隔离、移入回收站、恢复或永久删除；审批绑定固定 Call ID，避免批准后请求参数发生变化。

## 3. 任务与对话管理

- 任务和对话支持重命名、标签、置顶、归档和批量删除。
- 危险操作使用固定对象快照，重新选择后旧批次不能继续执行。
- 未绑定任务的合法调用保留独立入口。
- 旧数据继续读取，缺少新字段时保持未知，不伪造默认成功或零耗时。
- 对话、任务、调用和命令会话的归属在服务端统一维护。

## 4. 权限与审批模式

　　提供只读、规则审批和完全权限三种执行模式。显式禁止规则始终有效；完全权限不会覆盖明确 Deny。

　　审批针对固定请求和固定 Call ID。需要审批的操作在批准前不会执行，拒绝、取消或请求变化后不能沿用旧批准。控制面板可以查看审批状态和对应调用。

## 5. Windows 运行与兼容性

　　Windows 版本切换会检查已保存执行策略的兼容性，并补充工作区目标规范化、Git 错误诊断和旧任务数据处理。安装、回退和当前 Core 选择继续使用既有事务边界。

## 6. 历史限制

　　1.1.2 完成了数据模型和管理能力扩展，但界面仍存在任务/对话导航重复、卡片偏高、说明文字较密和旧任务展示不够清晰等问题，这些在 1.1.3 的界面重构中处理。
