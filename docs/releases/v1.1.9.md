# AgentDock Workbench 1.1.9

　　1.1.9 为预发布版本，相对 1.1.8 完善 Android 安装、连接与数据管理，改进 Windows 活动中心并新增 ChatGPT 目标模式，增加跨平台外部 Agent 接入入口。同时整理工具契约、长输出分页和异步命令收尾，降低重复上下文开销，改善旧版本安装升级兼容性。

## Android 界面与导航

　　菜单使用分组导航与统一图标，调整条目间距、明暗主题和卡片层级。窄屏保留底部常用入口，宽屏导航轨与页面内容使用相同的顶部安全区域，避免标题栏遮挡和重复留白。既有功能入口、返回操作和页面状态继续保留。

　　首页使用“设备概览”，连接、设置与部署页面改用面向操作的短文案。记录标识、构建信息、详细回执和高级参数通过“技术详情”等入口展开，日常页面优先显示状态、结果与可执行操作。

## Android 启动与运行环境

　　修复发布包裁剪后数据库构造器缺失导致的启动崩溃。后台任务组件改为按需初始化，降低 Shizuku 拉起应用时与启动初始化链的耦合，原有权限边界保持不变。

　　Termux 部署页面分别提示未安装、权限缺失、服务不可用、启动受限和回执待确认。增加打开 Termux、进入系统设置及返回后重新检测的入口。检测由用户明确触发，未收到回执的安装或写入操作不会自动重放。

　　环境准备脚本使用非交互包管理方式，处理未完成的软件包配置并保留已有配置文件。各安装阶段有等待上限，结束前检查软件包配置状态。已有 Debian 环境继续复用，容器列表读取失败时停止并报告问题。

　　Android 发布改为单一自包含 APK。当前版本的 Linux ARM64 Core 直接打入 APK，完整 Termux 桥包将其导入私有目录；“安装与更新”从本地内置归档部署，核对摘要、安全解包结构和 Core 自报版本后完成切换与启动。用户只需下载 Android APK，不再需要单独的 Core 归档、部署清单或分离签名。

　　尚未安装本机 Core 时，部署页明确说明任务、活动和调用页面需要先安装 Core。连接被拒绝、凭据未授权和 Core 未安装分别显示对应状态，避免把缺少运行时统一描述为不可操作的数据读取错误。

　　本机配对完成后立即刷新 Core 连接与数据读取状态，可以直接进入任务、活动和设置页面。内置 Core 部署不依赖额外网络下载；恢复未完成事务时仍核对原操作绑定的归档摘要和运行身份。

　　Android 节点仍需要外部 Termux 与 Linux 环境。部分手机会限制后台启动，请先打开 Termux，并按页面提示检查系统的应用启动管理。公开 APK 改用固定发布签名，后续同一包名的更新可以保留应用数据。此前下载过临时测试签名 1.1.9 的设备需要先保存重要配置并卸载旧包，完成一次签名身份迁移。

## Android 文件与环境清理

　　Core、凭据、对话、任务、日志和运行时临时数据保留在应用或 Termux 私有目录。默认工作区使用用户可访问的 `Documents/AgentDock/Workspaces`，交付制品使用 `Documents/AgentDock/Artifacts`。旧私有工作区迁移提供预览、校验和确认步骤，并保留工作区标识。

　　私有缓存、废弃安装事务、诊断文件和 Core 日志增加有界自动清理。Shizuku 临时文件统一放入 `/data/local/tmp/agentdock-workbench` 的会话子目录，便于按终态和有效期回收。

　　完整环境卸载提供预览和显式确认，清除 AgentDock 私有 Core、桥脚本及专属 PRoot 环境。公共工作区、公共制品、共享 Termux 软件包与外部 PRoot 环境继续保留。

## Windows 活动中心与目标模式

　　右键选择 `file_edit` 执行记录后，可在文件资源管理器中定位编辑目标。多文件编辑提供路径子菜单，移动操作优先定位目标路径，文件已删除时定位仍存在的上级目录。历史记录缺少可解析的本机路径时显示禁用说明，不使用当前工作区推测旧记录的位置。

　　修复实时执行记录到达时左侧对话目录短暂折叠再展开的问题。刷新保留项目状态和用户主动折叠的选择，迟到的旧记录不再临时覆盖整个项目的展开状态。

　　对话大标题右侧显示开始时间，格式为 `yyyy-MM-dd HH:mm`，使用本机时区。时间取自对话创建记录，未知时保持隐藏。工具搜索、检查及列举记录使用对应操作名称，避免统一显示为“执行工具”。

　　调用详情与记录管理操作重新归并，减少同一功能在多个位置重复出现。对话继续作为任务中心的主要层级，常用操作与低频管理操作分别组织。

　　常规命令观察在当前视图中归并到原始命令的“观察”入口，点击后展开各次调用。空输出且状态正常的观察默认收起，有新输出、执行错误或输出缺口的记录保持可见。搜索、筛选、原始审计和导出继续保留每次独立调用。

　　对话标题右侧新增“目标模式”。手动选择已有 ChatGPT 标签页并确认绑定关系后，托盘服务读取对应任务、分支和页面的真实状态。任务仍在执行范围内、上一轮回答已结束且稳定静默满五分钟时，发送一次“当前任务尚未完成，请继续任务”，并核对新消息回执。新的任务进展出现后，才进入下一轮静默观察。

　　页面生成中、存在草稿或附件、待审批以及后台命令仍运行时保持观察。任务结束、绑定变化、登录失效或发送结果待确认时停止或暂停接续。开启隐藏页面接续后，原标签页关闭时可在同一浏览器会话中恢复。浏览器的本机调试端点与 AgentDock 托盘需要保持运行，重启后手动重新开启目标模式。入口同时提供停止和解除绑定操作。

## 外部 Agent 接入

　　Codex、Claude Code 和其他 MCP 客户端可以通过现有 `/mcp` 端点调用 AgentDock，复用工作区、权限、审批、任务与活动记录。Windows 控制面板和 macOS 菜单栏增加“外部 Agent”配置入口，Linux 使用 `agentdock external-agent` 命令生成配置。Android 沿用共享 Core 协议，本版保持现有移动端页面。

　　生成的配置支持本机与公网端点，以及 OAuth 或 Bearer 认证。Bearer 配置使用环境变量引用，实际凭据由调用方的受信环境提供；公开配置和连接提示词只包含连接方式与必要参数。

## 工具调用、上下文与发现恢复

　　`mcp_tool_call`、`exec_command`、`read_file` 等内置工具直接使用调用方的宿主工具入口。将内置工具误送入动态 MCP 搜索或检查时，系统返回已解析的宿主入口、停止重复发现的指引和未执行标记，便于调用方转入正确工具。

　　同一对话绑定内短时间重复发现同一个内置工具时，系统会识别重复误路由并停止继续引导动态搜索。别名、大小写和搜索数量变化不会绕过识别。重复状态按对话与工作区绑定隔离并设有有效期，不影响正常业务调用，也不会永久限制上下文恢复后的合法目录或 Schema 重读。

　　混合检查同时包含内置工具与动态工具时，保留已成功读取的动态工具定义，并逐项说明内置工具的正确入口。明确指定动态服务及其同名工具时，继续执行原有认证、权限和调用规则。插件展开后优先复用已经返回的工具目录，仅在缺少 Schema 或能力版本变化时读取相应定义。

　　中英文 README 增加 MCP Server 目录 `description` 配置说明，提供可直接粘贴的设备委派、上下文初始化与复用描述。

　　内置工具按能力分组提供按需入口，Android 设备系统工具随执行器可用性显示。完整上下文增加稳定修订标识；调用方明确携带已经持有的 `known_context_revision` 时，服务端重新核对规则、工作区、任务和工具可见性，再决定返回完整上下文或紧凑引用。上下文丢失后省略该参数即可重新取得完整内容。

　　命令会话按实际返回的字节推进输出游标。长输出达到单次读取预算后，后续 `session_observe` 可以继续读取缓冲区内剩余内容，UTF-8 多字节字符保持完整。会话列表返回简短摘要，状态查询保留执行状态、退出码和必要输出。

　　文本搜索、目录列举、MCP 目录与上下文结果增加结构化分页。后续页面读取同一保留快照，并校验原始筛选条件和所属工作区、任务与调用方。单个条目超过页面上限时返回明确说明和可用的原始记录入口，输出同时区分源数据完整性与当前页面交付范围。

　　后台命令通过共享终态通知更新审批和执行记录，命令完成事件持久化后再确认收尾结果。取消单个等待者保持命令与其他观察者独立，停止、超时和关闭过程统一处理重复或迟到的完成通知。

　　异步命令的完成摘要会随同一对话后续的 AgentDock 根调用附带，保留命令原属任务、退出码与活动事件标识，完整输出仍按需读取。摘要使用独立的运行时事实字段，与用户中途补充分开处理；已经直接读取的终态保持去重。系统记录摘要已加入响应后的状态，传输结果未知时保留活动记录供核对。

　　运行中命令改为建议先处理独立工作。默认前台等待延长到10秒，需要等待结果时使用5秒、15秒或60秒的自适应窗口，显式等待最长支持300秒。完成通知复用后续调用，宿主没有继续调用时仍需由当前任务的等待操作取得结果。

　　公共输出 Schema 复用共享字段定义，通用处理指令集中在初始化上下文。普通成功响应精简重复的权限配置和绑定说明，动态执行指引、中途补充消息、异常诊断与审批信息继续保留。

　　公开工具定义与完整验证契约分别管理，业务字段和执行封装复用同一份定义。上下文引用、结构化分页与命令输出使用一致的契约，嵌套字段、审批分支和特殊字段名继续按原有规则校验。

　　保存线程检查点后返回保存状态、当前步骤、进度数量和活动引用。完整线程内容继续保存在任务状态中，通过 `thread_get` 按需读取。

　　已终止对话支持解除终止，恢复接收新的工具调用。此前已经停止的命令保持其终态，后续操作依据当前任务进度重新发起。任务绑定、取消和快照处理加强跨对话、跨工作区隔离。

　　下游 MCP 调用通过 `tools/call._meta` 携带经校验的宿主对话标识，便于服务区分并稳定复用不同对话的会话状态。标识取自已验证的执行上下文，与任务线程分别管理，HTTP 与 stdio 调用保持一致。第三方工具参数和 Schema 沿用原有契约，目标绑定与权限判断继续由接收服务负责。

　　需要审批的 MCP 调用固定准备阶段的服务器配置、连接代次、目录修订和工具定义，并在派发前再次校验。审批期间发生定义变化时保留未执行状态，要求重新检查，避免将旧审批应用到已经变化的操作。

## Windows 安装与升级

　　Windows 安装、修复及同版本升级在切换计划任务后，会继续按安装路径停止旧的托盘与 Core 进程，并等待稳定入口和当前、回退版本的可执行文件解除占用后再替换。这样可避免后台进程尚未退出时出现文件占用、激活失败或回滚失败。

　　安装器兼容从 1.1.0 起的历史安装日志与权限格式。备份和回滚保留目录访问控制与文件属性，适配由系统、管理员或历史账户拥有的文件，修复 `restore backup security stream`、无效所有者和部分旧事务恢复错误。升级、同版本修复与卸载继续保留对应的用户数据处理规则。

　　控制面板增加 `pwsh`、`cmd` 和 Git Bash 运行环境选择，默认沿用 `pwsh`。公网健康检查补充 Windows 系统网络配置兼容处理，使状态面板更准确地反映实际可达性。
