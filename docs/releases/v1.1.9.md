# AgentDock Workbench 1.1.9

　　AgentDock Workbench 1.1.9 将 Windows、macOS、Linux 与 Android Workbench 纳入正式发行通道，并修复工具发现循环、Computer Use 误加载、插件来源确认丢失、Windows 侧栏刷新抖动和发布事务恢复问题。全部公开安装包由同一提交完成平台验证后发布。

## 1. 内置工具与动态 MCP 路由

- `exec_command`、`task_manage`、`file_edit` 等内置工具使用独立的宿主命名空间。精确搜索只返回紧凑的 `host_builtin` 终止路由，不再回传完整输入/输出 Schema，也不再出现“已经命中但 `count=0`”的矛盾状态。
- `exec_command exact`、`host task_manage` 等带路由修饰词的查询会归一化到真实内置工具；`write_file`、`run_command`、`shell_command`、`task_update` 等兼容名称会返回明确的宿主工具映射。
- `mcp_tool_inspect` 收到裸内置工具名时返回 `HOST_BUILTIN_NOT_DYNAMIC_MCP`，直接指向宿主调用路径，不再诱导模型继续猜测 `server:tool`。
- 动态工具匹配要求工具标识符真实覆盖名称或标题，避免仅凭描述中的普通词把 `exec_command exact` 误匹配到 GitHub `search_code`。
- 活动中心使用“定位内置工具”或“识别内置工具”展示最终路由，第三方 MCP 返回值不能伪造活动标题或隐藏计数。

## 2. Computer Use 显式加载

- Computer Use 只在任务明确要求操作网页或 Windows 图形界面时加载。
- 代码、文件、Git、终端、PCB、API 和普通 MCP 任务不会因能力探测而引入桌面控制工具。
- 启动应用需要明确的桌面交互意图和具体原因，恢复会话、查找已有窗口或获取进程信息不会误启动程序。

## 3. 插件更新与来源确认

- 插件本地更新的 `confirmed_source_change` 会完整穿过共享 Runtime API，不再在管理接口转发时丢失。
- 来源变化仍需显式确认；合法确认可以到达插件服务，未确认的来源切换继续被拒绝。

## 4. Windows 侧栏稳定性

- 项目活动刷新不会重建已有分组容器，展开状态、排序和当前选择保持稳定。
- 新项目按当前规则增量加入，已删除项目增量移除，后台活动变化不再造成侧栏闪动或分组跳动。

## 5. 正式发布事务

- 发布器以单一已验证提交为源，校验 Windows、macOS、Linux、Android 构建报告和安装验证，再组装公开安装包。
- 发布过程先创建或恢复 GitHub Draft Release，核对远端资产名称、大小和 SHA-256 后再转为正式版；失败时保留可检查的事务状态，不重复创建发布。
- 正式版设置为 GitHub Latest，既有 `v1.1.8` 预发布标签和资产保持不变。
