# AgentDock Workbench 1.1.9

　　1.1.9 为预发布版本，相对 1.1.8 改进 Android 导航与运行环境，完善 Windows 活动中心并新增 ChatGPT 目标模式，同时改进长输出读取、工具上下文开销、下游 MCP 对话标识传递与重复发现恢复。

## Android 界面与导航

　　菜单使用分组导航与统一图标，调整条目间距、明暗主题和卡片层级。窄屏保留底部常用入口，宽屏导航轨与页面内容使用相同的顶部安全区域，避免标题栏遮挡和重复留白。既有功能入口、返回操作和页面状态继续保留。

　　首页使用“设备概览”，连接、设置与部署页面改用面向操作的短文案。记录标识、构建信息、详细回执和高级参数通过“技术详情”等入口展开，日常页面优先显示状态、结果与可执行操作。

## Android 启动与运行环境

　　修复发布包裁剪后数据库构造器缺失导致的启动崩溃。后台任务组件改为按需初始化，降低 Shizuku 拉起应用时与启动初始化链的耦合，原有权限边界保持不变。

　　Termux 部署页面分别提示未安装、权限缺失、服务不可用、启动受限和回执待确认。增加打开 Termux、进入系统设置及返回后重新检测的入口。检测由用户明确触发，未收到回执的安装或写入操作不会自动重放。

　　环境准备脚本使用非交互包管理方式，处理未完成的软件包配置并保留已有配置文件。各安装阶段有等待上限，结束前检查软件包配置状态。已有 Debian 环境继续复用，容器列表读取失败时停止并报告问题。

　　Android 发布现在同时提供 Linux ARM64 Core 归档、签名部署清单和独立 Ed25519 签名。完整 Termux 桥包加入固定发布公钥，bootstrap 将其安装到 Termux 私有信任目录；“安装与更新”预填当前版本的官方清单和签名地址，可在核对签名、架构、版本、SHA-256、归档结构和 Core 自报身份后完成安装并启动。

　　尚未安装本机 Core 时，部署页明确说明任务、活动和调用页面需要先安装 Core。连接被拒绝、凭据未授权和 Core 未安装分别显示对应状态，避免把缺少运行时统一描述为不可操作的数据读取错误。

　　Android 节点仍需要外部 Termux 与 Linux 环境。部分手机会限制后台启动，请先打开 Termux，并按页面提示检查系统的应用启动管理。公开 APK 改用固定发布签名，后续同一包名的更新可以保留应用数据。此前下载过临时测试签名 1.1.9 的设备需要先保存重要配置并卸载旧包，完成一次签名身份迁移。

## Windows 活动中心与目标模式

　　右键选择 `file_edit` 执行记录后，可在文件资源管理器中定位编辑目标。多文件编辑提供路径子菜单，移动操作优先定位目标路径，文件已删除时定位仍存在的上级目录。历史记录缺少可解析的本机路径时显示禁用说明，不使用当前工作区推测旧记录的位置。

　　修复实时执行记录到达时左侧对话目录短暂折叠再展开的问题。刷新保留项目状态和用户主动折叠的选择，迟到的旧记录不再临时覆盖整个项目的展开状态。

　　对话大标题右侧显示开始时间，格式为 `yyyy-MM-dd HH:mm`，使用本机时区。时间取自对话创建记录，未知时保持隐藏。工具搜索、检查及列举记录使用对应操作名称，避免统一显示为“执行工具”。

　　对话标题右侧新增“目标模式”。手动选择已有 ChatGPT 标签页并确认绑定关系后，托盘服务读取对应任务、分支和页面的真实状态。任务仍在执行范围内、上一轮回答已结束且稳定静默满五分钟时，发送一次“当前任务尚未完成，请继续任务”，并核对新消息回执。新的任务进展出现后，才进入下一轮静默观察。

　　页面生成中、存在草稿或附件、待审批以及后台命令仍运行时保持观察。任务结束、绑定变化、登录失效或发送结果待确认时停止或暂停接续。开启隐藏页面接续后，原标签页关闭时可在同一浏览器会话中恢复。浏览器的本机调试端点与 AgentDock 托盘需要保持运行，重启后手动重新开启目标模式。入口同时提供停止和解除绑定操作。

## 工具调用、上下文与发现恢复

　　`mcp_tool_call`、`exec_command`、`read_file` 等内置工具直接使用调用方的宿主工具入口。将内置工具误送入动态 MCP 搜索或检查时，系统返回明确的非重试型路由错误，指出正确入口，并明确说明该次请求没有执行命令或业务操作。

　　同一对话绑定内短时间重复发现同一个内置工具时，系统会识别重复误路由并停止继续引导动态搜索。别名、大小写和搜索数量变化不会绕过识别。重复状态按对话与工作区绑定隔离并设有有效期，不影响正常业务调用，也不会永久限制上下文恢复后的合法目录或 Schema 重读。

　　混合检查同时包含内置工具与动态工具时，保留已成功读取的动态工具定义，并逐项说明内置工具的正确入口。明确指定动态服务及其同名工具时，继续执行原有认证、权限和调用规则。插件展开后优先复用已经返回的工具目录，仅在缺少 Schema 或能力版本变化时读取相应定义。

　　中英文 README 增加 MCP Server 目录 `description` 配置说明，提供可直接粘贴的设备委派、上下文初始化与复用描述。

　　命令会话按实际返回的字节推进输出游标。长输出达到单次读取预算后，后续 `session_observe` 可以继续读取缓冲区内剩余内容，UTF-8 多字节字符保持完整。会话列表返回简短摘要，状态查询保留执行状态、退出码和必要输出。

　　公共输出 Schema 复用共享字段定义，通用处理指令集中在初始化上下文。普通成功响应精简重复的权限配置和绑定说明，动态执行指引、中途补充消息、异常诊断与审批信息继续保留。

　　保存线程检查点后返回保存状态、当前步骤、进度数量和活动引用。完整线程内容继续保存在任务状态中，通过 `thread_get` 按需读取。

　　下游 MCP 调用通过 `tools/call._meta` 携带经校验的宿主对话标识，便于服务区分并稳定复用不同对话的会话状态。标识取自已验证的执行上下文，与任务线程分别管理，HTTP 与 stdio 调用保持一致。第三方工具参数和 Schema 沿用原有契约，目标绑定与权限判断继续由接收服务负责。

## 安装包

| 平台 | 安装包 |
| --- | --- |
| Windows x64 | `AgentDockSetup-amd64.exe` |

| Debian / Ubuntu x64、ARM64 | 对应架构的 `.deb` |

| Android | `AgentDock-Workbench-1.1.9-Android.apk` |
