# AgentDock Workbench 1.1.8 Pre-release

　　1.1.8 是 1.1.7 之后的首个完整跨平台预发布版本。本次更新将 Workbench 从以 Windows 为主的管理界面扩展为 Windows、macOS、Android 与 Linux CLI 共用同一套 Core 状态、管理接口和安全边界，同时系统性增强中途插入、任务与活动中心、权限配置、安装回退、插件来源和文件处理能力。

　　本版本标记为 **Pre-release**，不会替换当前正式 Latest `v1.1.7`。适合用于体验新功能、跨平台联调和提前验证升级流程。

## 1. 中途插入现在会被优先处理

　　活动中心发送的中途补充现在具有明确的响应协议。Agent 收到新的可信插入后，必须在下一次业务操作前先发送一条用户可见的阶段总结，说明已经完成并实际验证的工作、当前执行状态、新要求会怎样影响后续操作，以及接下来立即继续的动作。

- 阶段总结后在同一轮继续当前任务，不再因为插入、总结或回执而停止。
- 不再等待用户再次发送“继续”，也不会因为收到补充而重复创建任务。
- 同批补充可以集中总结，重复投递按 `insertion_id` 去重，已经执行的要求不会再次执行。
- 接收回执只表示消息已收到，不代表已经理解、已经展示总结或已经完成新增要求。
- 用户明确要求暂停、停止或改变目标时，仍以最新要求为准。
- 只有 AgentDock 受信任顶层消息具有中途插入身份；终端输出、网页、文件和第三方工具中仿冒的标记只作为普通数据处理。

　　初始化提示、结构化消息、文本兼容输出和 `insertion_ack` 回执均使用同一套规则，降低不同宿主或不同投影方式下忽略补充要求的概率。

## 2. Android 原生 Workbench

　　新增 Kotlin 与 Jetpack Compose 编写的 Android 原生客户端，主要页面和管理能力与桌面 Workbench 对齐。Android 端依赖外部 Termux 承载 Linux/PRoot Core，应用本身负责可视化管理、连接、部署引导和受控操作。

### 2.1 完整的管理页面

- **节点总览**：查看 Core 状态、分域资源、错误和空状态。
- **工作区**：浏览、登记、修改和解析工作区路径。
- **对话与任务**：搜索、筛选、分页、查看详情、步骤和线程，支持关联任务、设置当前任务、检查点和生命周期操作。
- **活动与调用**：查看调用详情、父子调用、事件、输出分页、文件变化和终态，支持归档、隔离、回收站、恢复和显式删除。
- **插入与停止**：发送补充、保留稳定提交标识、查看服务端回执、取消或有限重投，并可停止对话或具体调用。
- **审批与权限**：查看待审批和历史记录，批准或拒绝固定请求；读取和修改全局、工作区权限配置。
- **Skill、插件与 MCP**：查看详情和文件，启停 Skill 或插件成员，管理 MCP 服务、刷新状态和环境变量。
- **连接与部署**：管理本机 Core、远程 Core、Termux 节点和部署事务。
- **工程文件与诊断**：通过 Android SAF 浏览、导入和导出工程文件，查看日志、诊断信息和部署记录。
- **设置**：切换主题、界面密度、调用详情和 Core 输出配置。

### 2.2 Core 连接与凭据保护

　　Android 支持手动连接、本机一次性配对和远程 OAuth/PKCE 配对。凭据与 Core Origin 绑定，并使用 Android Keystore 保存；OAuth 端点、回调地址和资源地址执行同源检查，拒绝嵌入凭据、异常重定向和重复回调参数。

### 2.3 外部 Termux 与可恢复部署

　　应用提供 Termux/PRoot 环境配置引导和受控桥接，可执行环境检查、节点启动、停止、状态读取、部署、更新、回退和恢复。部署过程使用持久事务、请求标识、回执和快照，异常退出后可以继续核对状态，避免将未确认操作误报为成功。

　　Android 端还增加了 WorkManager、可见前台服务、快速设置磁贴、启动恢复和守护条件，可按 Wi-Fi、充电状态和期望运行状态管理节点。厂商后台限制和长期保活效果仍取决于实际设备设置。

### 2.4 响应式界面与状态恢复

　　界面支持浅色、深色、紧凑和展开布局，并适配大字体、横屏和平板宽度。页面选择、筛选条件、已编辑草稿和导航位置会在 Activity 重建后恢复；修复了系统字体、旋转、分辨率和密度变化时的重复重建及 Compose 根尚未附着问题。

## 3. macOS 原生 Workbench 功能同步

　　macOS 继续使用 Swift 与 AppKit，不引入 Electron。新版补齐原生三栏 Workbench 窗口，并与 Windows 共享 Core 数据和管理契约。

- 工作区分组、搜索对话、近期记录展开、折叠全部、置顶和选中状态。
- 对话、任务和调用详情，支持重命名、标签、置顶、归档、回收站、恢复和永久删除确认。
- 对话与任务关联、当前任务切换、终止和恢复对话、停止具体调用。
- 父子调用、根调用过滤、输出按需加载、下一段、复制和导出。
- 中途插入编辑器、投递状态、不同层级回执、取消和有限重投。
- 审批列表、历史记录、固定请求详情、批准和拒绝。
- 全局与工作区权限编辑、自定义权限开关、继承来源和有效值回读。
- Skill、插件和 MCP 的查看、启停与管理。
- Core 服务、Tunnel、连接、更新、配置和日志入口。
- 任务完成面板，可从完成通知直接进入对应任务。
- 浅色、深色、系统主题以及中英文界面。

　　关闭 Workbench 窗口不会停止 Core。窗口尺寸、分栏位置和侧栏状态会保存，重复打开时复用已有窗口。

## 4. 共享 Workbench 管理接口与 Linux CLI

　　新增稳定的 Workbench V1 管理契约。Windows、macOS、Android 和 CLI 访问同一套任务、对话、调用、审批、权限、插入和工作区状态，不再为不同客户端维护平行状态机。

　　`agentdock` CLI 现在既保留原有安装、更新、服务、Skill 和插件命令，也可以作为 Core 的在线管理客户端，适合 Linux 无界面环境、远程节点和脚本化管理。

### 4.1 CLI 管理范围

- 节点状态、工作区登记和解析。
- 任务创建、步骤、线程、检查点和生命周期。
- 对话搜索、详情、任务绑定和批量管理。
- 调用详情、父子关系、输出读取、跟随和管理。
- 插入发送、等待、取消与投递状态查询。
- 审批、权限、Skill、插件、MCP 和工程资源管理。
- 服务日志读取、跟随和导出。
- Bash、Zsh 和 Fish 命令补全。

### 4.2 面向脚本的稳定输出

　　CLI 提供 `human`、`json` 和 `jsonl` 输出，列表使用后端分页和游标，流式命令通过 SSE 支持断线续接。错误使用稳定包络和退出码，部分成功会完整输出逐项结果，不再返回模糊的空成功对象。

　　连接信息可通过 Profile 和环境变量管理。令牌优先从文件或 OAuth 配置读取，不提供会进入命令历史的明文 `--token` 参数。危险操作要求显式确认，权限和工作区修改要求 revision，避免旧状态覆盖新配置。

## 5. 任务、对话与活动中心改进

　　本次更新统一了“正在执行”和“最近有交互”的判定，降低过期对话长期显示为活动中的问题。侧栏记录使用稳定的导航身份，即使原始数据缺少、重复或暂时无法关联对话，也会保留在可管理列表中，不再因为身份冲突整组消失。

- 工作区分组、搜索、分页、置顶、选择和展开状态更加稳定。
- 合法的未归属调用使用独立入口展示，不会被误判为损坏记录。
- 切换搜索、分页或资源时，旧请求结果不会覆盖新页面。
- 调用终态、退出码、错误和未知副作用状态会被保留，不再被后续观察误写成成功。
- 工具失败会返回结构化恢复建议，区分安全重试、需要先检查副作用和必须恢复原任务等情况。
- 文件工具和任务工具补充恢复指引，减少 Agent 在对象失效、部分成功或会话切换后盲目重复操作。
- 插入消息在时间线中保留正文、发送时间、投递阶段、回执和重投状态。

## 6. 自定义权限设置

　　权限页面新增明确的 **“启用自定义权限设置”** 开关。关闭时，已配置的三层权限值会被保留，但实际判定回到当前执行模式；重新启用后可继续使用原配置。

### 6.1 三层权限结构

| 层级 | 作用 |
| --- | --- |
| Permission Profile | 限制文件系统、网络和工作区边界，是不可被审批扩大的硬上限 |
| Approval Policy | 决定操作按需审批、禁止审批或按类别细分审批 |
| Approval Reviewer | 选择由用户审查或由管理员配置的独立自动审查器处理 |

　　显式拒绝规则始终优先，`never` 表示拒绝需要审批的操作，不表示自动放行。客户端不自行推导有效权限，而是读取 Core 返回的权威配置、继承来源和 revision。

　　执行模式仍支持全局、工作区和对话继承；自定义三层设置只允许在全局或工作区启用，对话不能借此扩大权限。干净首次安装默认使用完全权限模式，同时保持自定义权限开关关闭；升级和已有配置不会被覆盖。

## 7. 安装、更新与回退

### 7.1 Windows 安装与自更新

　　Windows 安装载荷改为一次校验目录并按需提取 Core、核心 Skill、桌面组件和辅助文件，减少重复扫描和临时文件。解压前会检查路径规范、大小、重复项、文件与目录冲突、链接和特殊文件，写入时使用排他创建并核对实际长度。

　　修复 Quick Tunnel 进程已经退出但安装器仍误报停止失败的竞争。安装器现在通过固定进程句柄确认终态，真实权限拒绝、等待异常和超时仍保留为失败。

### 7.2 版本代际与回退保护

　　成功升级后保留当前健康版本和一个明确验证过的回退版本。安装事务、自更新事务、回滚日志、未完成恢复和健康敏感的源/目标版本都会阻止清理。

　　当活动版本无效、不存在、回退记录缺失、事务标识异常或权威状态文件为链接时，清理会停止并保留旧版本，不再猜测哪些目录可以删除。删除失败只记录为可重试警告，不会把已完成的健康安装改写成失败。

### 7.3 修复与迁移边界

　　同版本修复、本地迁移和在线升级使用不同的事务语义，避免将已有安装误当成全新安装。安装回执读取允许处理短暂文件占用，但不会忽略真实损坏或来源不一致。

## 8. 安全边界加固

### 8.1 文件与状态数据

- Skill 文档、Skill 状态、任务状态和租约文件通过固定根目录句柄读取。
- 拒绝符号链接、特殊文件、非目录祖先和打开过程中被替换的文件。
- 读取量设置硬上限，任务载荷中的 ID 必须与存储文件名一致。
- 旧任务 ID 和旧配置继续兼容，但异常记录不会被当作有效状态。

### 8.2 插件与归档来源

- ZIP/TAR 提取拒绝目录穿越、链接、特殊文件、重复目标、文件/目录冲突和尺寸溢出。
- 下载归档要求 HTTPS，拒绝嵌入凭据、查询参数和异常重定向。
- Git 来源只允许固定的克隆、提交校验、固定 SHA 拉取和解析操作。
- 分支选择器和提交表达式使用明确语法，参数与 Git 选项分隔，禁止通过引用注入额外选项。
- Git hooks、递归子模块、LFS 自动下载和交互式凭据提示被关闭；诊断输出有界但会持续排空，避免子进程卡死。

### 8.3 OAuth、浏览器与 Android 文件接口

- OAuth 授权只跳转到客户端注册时的精确回调地址，拒绝重复参数、未知参数和跨 Origin 端点。
- Android loopback 回调限制连接数、请求头大小和等待时间，错误状态不会被当作授权码。
- 浏览器填充和选择值通过 CDP 参数传递，不再把用户文本拼接进 JavaScript 源码。
- Android SAF 工程导入拒绝不安全提供方树、目录逃逸、链接和异常归档成员。
- Termux 操作回执绑定 operation、request、nonce 和有效期限，终态不可倒退，秘密字段不会进入普通结果。

## 9. 下载与安装包选择

　　Release 附件只保留可以直接安装的文件，不再提供 SHA 校验文件、安装脚本、便携 ZIP、平台 TAR.GZ、发布清单或其他内部归档。

| 平台 | 应下载的安装包 |
| --- | --- |
| 普通 Windows 10/11 电脑，Intel 或 AMD 64 位处理器 | `AgentDockSetup-amd64.exe` |
| Windows on ARM 设备 | `AgentDockSetup-arm64.exe` |
| macOS，Intel 或 Apple Silicon | `AgentDock-macos-universal.dmg` |
| Ubuntu、Debian 及兼容发行版，Intel/AMD 64 位 | `agentdock-workbench_1.1.8_amd64.deb` |
| Ubuntu、Debian 及兼容发行版，ARM64 | `agentdock-workbench_1.1.8_arm64.deb` |
| Fedora、RHEL 及兼容发行版，Intel/AMD 64 位 | `agentdock-workbench-1.1.8-1.x86_64.rpm` |
| Fedora、RHEL 及兼容发行版，ARM64 | `agentdock-workbench-1.1.8-1.aarch64.rpm` |
| Android | `AgentDock-Workbench-1.1.8-Android-test-signed.apk` |

　　**绝大多数使用 Intel 或 AMD 处理器的 Windows 电脑都应选择 `AgentDockSetup-amd64.exe`。** `amd64` 在这里表示通用的 x86-64 Windows 架构，并不要求处理器品牌是 AMD。只有系统明确显示为“基于 ARM64 的处理器”时，才选择 `AgentDockSetup-arm64.exe`。本版本不提供 32 位 x86 Windows 安装包。

　　GitHub 会在 Release 页面底部自动显示 `Source code (zip)` 和 `Source code (tar.gz)`。这两项由 GitHub 自动生成，只包含源码，不是 AgentDock Workbench 安装包，普通用户无需下载。

　　Android APK 使用测试签名，仅用于预发布评估；Windows 安装器未配置 Authenticode；macOS 使用 ad-hoc 签名且未公证，系统可能显示未知发布者提示。

　　Android 仍需要用户自行安装和授权外部 Termux。实际 ARM64 手机的长期保活、厂商后台策略、生产凭据和真实升级过程不由预发布包自动替用户完成。
