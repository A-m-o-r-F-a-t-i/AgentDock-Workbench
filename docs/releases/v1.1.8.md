# AgentDock Workbench 1.1.8 Pre-release

　　本次为用户指定的 1.1.8 预发布版本，汇集 1.1.7 之后的 Workbench 跨平台更新、Android 修复、安全审查整改和中途插入行为增强。GitHub 标记为 Pre-release，不替换现有正式 Latest。此前曾撤回的误标版本已归入 1.1.7，本次使用新的 1.1.8 源码和构建产物。

## 中途插入：先阶段总结，再继续任务

　　初始化提示、真实插入消息、文本兼容输出及接收回执共用新的响应协议。Agent 收到新的中途补充后，应在下一次业务工具调用前用进度消息说明已验证进展、当前状态、补充要求的影响和下一步，随后在同一轮继续当前任务。总结不作为终止答复，不等待用户再次说“继续”。

　　按消息标识去重，同批要求可以集中总结。用户明确停止、暂停、变更目标，以及真实权限或安全限制仍有效。接收回执只确认收到消息，不虚构模型已经理解、阶段总结已经展示或任务已经完成。投递期限、权限边界和不重跑原业务工具的规则保持不变。

## Android Workbench

　　包含 Kotlin/Compose 工作台页面、任务与对话、插入和停止、权限设置、Skill/MCP 管理、项目文件、连接与部署入口，以及外部 Termux 的配置引导与受控桥接。

　　修复系统配置变更与手动 Activity 重建竞争，并等待当前 Activity、已附着 Compose 根和导航语义节点共同就绪。Android 构建纳入同源码的完整发行流程。五 API 矩阵取消、失败、缺少测试报告或截图时禁止通过汇总门禁；预先初始化 ADB，避免模拟器冷启动时并发拉起 ADB 服务；启动步骤、测试与诊断收集具有独立时间边界，便于保留失败证据。

## 安全和可靠性

　　修复 Skill 文档、读租约和状态元数据的文件边界，使用固定目录句柄并限制实际读取量。ZIP/TAR 提取增加尺寸溢出检查、根内写入和实际长度校验。任务状态校验载荷 ID 与文件名一致性，同时保留合法旧版记录。

　　Git 插件来源使用固定操作集、明确选项边界和有界诊断输出。拒绝归档条目后取消相关子进程，避免管道等待。OAuth 使用已注册回调值，浏览器输入通过 CDP 参数传递。

　　版本清理在活动版本无效或不存在、回滚事务标识异常、状态文件为链接时停止清理并保留旧文件，防止丢失回退数据。

## 1.1.7 后的其他更新

　　包含共享管理接口与 Linux CLI 补全、macOS 原生工作台功能同步、Windows 对话侧栏与活动状态修复、自定义权限配置、插入投递和回执状态展示、安装速度与回退版本管理，以及 Windows 隧道停止竞争修复。

## 产物和验证范围

　　Windows 提供 x64/ARM64 安装器和归档，Linux 提供 amd64/arm64 归档及 DEB/RPM，macOS 提供双架构 Core 和 Universal 应用，Android 提供文件名明确标记为 `test-signed` 的预发布 APK。版本、源码提交、平台验证结果与文件摘要写入 `release-manifest.json` 和 `SHA256SUMS`。

　　Android APK 使用测试签名密钥，仅供预发布评估。外部 Termux 安装和授权仍须用户确认，实际 ARM64 手机长时间保活、厂商后台策略和生产安装未作为本次自动化验收结果。Windows 产物未配置 Authenticode 发布签名，macOS 为 ad-hoc 签名且未公证，系统可能提示未知发布者。

　　插入协议回归验证本仓库的提示与传输路径，不等同于外部模型服从率测试。真实模型收到插入后是否正确总结并继续，应在连接到此版本后观察。
