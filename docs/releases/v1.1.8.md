# AgentDock Workbench 1.1.8 Pre-release

　　相对 1.1.7，1.1.8 是一次跨平台能力扩展。最大的变化是新增完整的 Android 原生 Workbench、Termux/PRoot 节点管理和受管手机执行体系，同时补齐 macOS 原生 Workbench、共享管理 API 与 Linux CLI，并继续改进 Windows 安装/自更新速度、任务与活动中心、原生深色界面、权限配置、中途插入、Agent 工具发现和安全边界。

　　本版本继续标记为 **Pre-release**。以下内容按 1.1.7 → 1.1.8 的用户可见变化组织。

## 1. Android 原生 Workbench：本版最大的新增能力

　　1.1.8 首次提供 Kotlin 与 Jetpack Compose 编写的 Android 原生 Workbench。Android 端不使用 Electron，也不在 APK 内复制一套 Core 状态机；任务、对话、调用、审批、权限、Skill、插件和 MCP 仍由 AgentDock Core 统一管理，手机应用负责原生界面、连接、部署和生命周期管理。

### 1.1 原生管理界面

- **节点总览**：查看 Core 状态、版本、连接信息、错误和节点操作状态。
- **工作区**：浏览、登记、修改工作区并解析实际路径。
- **对话与任务**：搜索、筛选和查看对话，读取任务步骤、线程、检查点和完成条件，并执行关联任务、设置当前任务等管理操作。
- **活动与调用**：查看根调用与子调用、命令、输出、耗时、错误、退出码和文件变化，并支持归档、隔离、回收站和恢复。
- **审批与权限**：查看待审批请求、历史记录和有效权限，管理全局或工作区权限设置。
- **Skill、插件与 MCP**：查看并启停能力，读取成员和详情，管理 MCP 服务及环境配置。
- **连接与部署**：管理本机 Core、远程 Core、Termux 节点、安装、更新、回退和恢复。
- **工程文件与诊断**：使用 Android SAF 浏览、导入和导出工程文件，并查看日志与部署记录。
- **设置**：提供主题、界面密度、调用详情、通知、守护和 Core 输出等选项。

### 1.2 Termux / PRoot 节点产品化

　　Android 端以外部 Termux 承载 Debian PRoot 中的 Linux ARM64 Core。APK 与 Termux 之间使用固定组件、固定脚本路径和封闭操作集通信，支持环境探测、节点启动、停止、状态查询、安装、更新、回退、恢复和诊断。

　　Termux `RUN_COMMAND` 回调现在按官方语义区分早期 ACK 与最终结果。空 ACK 不会提前结束操作，最终回执继续绑定原请求；原始输出长度、非零退出码和共享 UTF-8 截断预算分别处理。回调校验失败或输出被截断时保留 `unknown`，要求继续查询原操作，不会误写成成功或再次执行。

　　部署流程使用持久事务 journal，并将 operation ID、request ID、nonce 与结构化回执绑定。安装或更新中断后，可以继续查询原操作或恢复事务，不会把“请求已经发出但结果未知”误写成成功，也不会因为没有收到回执就直接重放有副作用的操作。

　　版本切换前会保留旧版本和数据恢复信息；新版本身份、鉴权、版本或工作目录检查失败时，可以恢复旧指针与数据。相同制品的重复安装不会错误覆盖已有回退版本，恢复窗口中的数据目录也不会被初始化逻辑提前改写。

### 1.3 守护、开机恢复与用户停止意图

　　Android 新增 WorkManager、前台服务、通知操作、快速设置磁贴和开机检查。守护可以结合 Wi-Fi、充电状态和配置的检查周期运行。

　　节点的“期望运行状态”独立保存。用户主动停止后会记录为 stopped，守护和自动恢复不会反向把节点重新启动。乱序回执不能覆盖更新的用户意图，恢复/查询类操作保留独立容量，避免普通未决操作占满队列后连状态查询和恢复都无法执行。

### 1.4 Core 连接、凭据与远程 OAuth

　　手动 Bearer 凭据与 Core 的 scheme、host 和端口绑定，并保存在 Android Keystore。明文 HTTP 只允许字面 loopback，远程连接需要显式启用 HTTPS。

　　本机配对使用一次性公钥交换；远程配对采用 OAuth/PKCE、随机 state 和临时 loopback 回调。OAuth 浏览器启动不再依赖 Android 包可见性预查询，端点、回调、重定向和资源地址继续执行严格同源检查。

### 1.5 工程文件、活动流与移动端稳定性

　　SAF 工程导入/导出增加路径、层级、单文件、归档和展开总量边界，ZIP 输出在写入中央目录时也计入大小限制。危险 Provider 树、路径逃逸、链接和异常归档成员会被拒绝。

　　活动和调用 SSE 改为可重新建立的客户端流，断线后保留游标并按当前连接重新订阅。配置变化、屏幕旋转和 Activity 重建时保留必要页面状态，减少重复生命周期动作。响应式界面继续适配窄屏、横屏、大字体和平板宽度。

　　Android 主题现在同时驱动 Compose 内容、状态栏和导航栏。手动浅色或深色模式会覆盖系统设置，跟随系统模式继续响应系统主题变化；API 26—34 同步系统栏背景与图标，API 35 及以上保留 edge-to-edge 和导航栏对比度规则，不改变页面布局或节点状态。

### 1.6 受管手机执行与结构化系统工具

　　除 PRoot Core 管理外，1.1.8 还新增显式选择的 Termux 主机执行后端。Core 继续拥有调用、权限、任务和会话，手机侧只执行已经接纳的原始操作。启动请求只投递一次，丢失回执保留 `unknown`；输出游标、输入确认、取消、截止时间和 PTY 由受管会话处理，阻塞输入不能绕过超时。

　　可选的 Shizuku 后端使用受保护 Binder 与 UserService 执行受管系统进程。该后端默认关闭，需要独立安装并授权 Shizuku，不会在 Termux 失败时自动接管。每个操作保留原始身份、进程组、输出上限和截止时间；晚到回调、服务重建或状态缺失不能触发第二次执行。实际权限取决于 Shizuku 服务的 UID，Android 11 及以上在设备重启后仍需按 Shizuku 的方式重新启动服务。

　　Core 新增 `android_device_read` 与 `android_device_act` 两个闭合参数的结构化工具，覆盖应用包、前台窗口、显示、系统属性、Settings、AppOps、日志、应用启动/停止、已有 APK 安装、组件与权限调整、输入事件、截图和 UI 层级导出。操作沿用原始 Core Call/Session 生命周期，不把参数拼成任意 Shell；有副作用的结果不明确时继续观察原会话，不因回调超时重复安装、输入或设置修改。截图和 UI 导出必须指定共享存储目录，只有原命令确认成功后才标记为可用。

## 2. Windows：安装、自更新和 Workbench 继续优化

### 2.1 安装与自更新速度优化

　　Windows 安装与自更新路径改为**单次校验、选择性解压**。Release ZIP 的目录只解析和校验一次，随后从同一份目录中流式提取 Core、Core Skill、桌面组件和辅助文件，减少过去重复扫描、重复解压和临时文件写入。

　　Windows Setup 不再依赖 PowerShell `Expand-Archive` 展开完整载荷。安装器会先检查 ZIP 中央目录、规范化 Windows 路径、重复项、文件/目录冲突、链接、特殊文件、条目数量和展开大小，然后只写入实际需要的文件。自更新和本地归档路径复用同一套安全提取逻辑。

　　安装器还记录 download、verify、extract、service stop/start、payload write、readiness wait 等阶段耗时，后续遇到安装慢或启动等待时可以直接定位具体阶段，而不必只看整段安装总时间。

### 2.2 版本保留、修复和回退

　　升级成功后，版本目录默认保留当前健康版本和一个明确记录的健康回退版本。活动版本、fallback、安装事务、自更新事务、回滚日志以及尚未结束的恢复引用都会阻止清理，避免为了节省空间误删仍有恢复价值的数据。

　　同版本修复、本地迁移和在线升级使用不同的事务语义。相同制品不会被错误当成新一代版本；短暂的安装回执文件占用可以等待恢复，真实损坏和来源不一致仍然保持失败。旧 Windows ZIP 分隔符、Quick Tunnel 已退出后的停止竞争以及安装回执共享竞争也进行了兼容处理。

### 2.3 Windows Workbench 交互修复

　　执行中心进一步收紧异步选择和操作边界。切换筛选、搜索或视图后会立即失效旧的“全选”集合，任务与分支操作绑定到当前真实选择，旧请求返回不能继续操作已经切换掉的任务。

　　终止对话现在独立于“最近 3 分钟可插入”的时间条件；即使已经不满足插入资格，只要对话本身仍可终止，终止入口仍然保留。设置保存和 Skill/插件能力修改采用单操作门禁，避免重复点击造成并发写入。执行记录导出也会固定实际目标范围，未归属调用和孤立历史记录不再因为 UI 选择变化而导出到错误对象。

　　Windows 公网状态检测与本地控制请求进一步分离。公网检测会在每次检查时重新读取当前 Windows 用户代理，代理端口切换或关闭后不再继续沿用已经失效的旧代理；本地 Core 健康检查和管理 API 固定直连 loopback，不受桌面代理故障影响。

　　Tailscale Funnel 长时间运行后若出现公网入口持续不可达，而本地 Core、设备身份和既有映射仍通过检查，Workbench 会在连续确认失败后刷新 AgentDock 确权的根路径映射，并设置恢复冷却时间。恢复过程不重启 Core 或整个 Tailscale 服务，不修改其他应用的 Serve/Funnel 路径；写入未能确认时保留未判定状态并执行受限回滚。公网手动检测遇到尚未收到 HTTP 响应的传输故障时，也会使用新的网络会话有限重试一次，不会重放已经收到响应的协议请求。

### 2.4 原生标题栏与深色模式

　　控制面板、活动中心以及后续打开的辅助窗口现在在同一次主题应用中同步 WPF 内容与 Windows 原生标题栏。手动浅色、深色和跟随系统切换会即时更新现有及后建窗口；Windows 11 同步标题背景和文字，高对比度恢复系统默认。窗口继续使用系统原生按钮、菜单、缩放和 DPI 行为，旧系统不支持的 DWM 属性保持原生外观，不阻断启动或主题切换。

## 3. macOS 原生 Workbench 功能大幅补齐

　　macOS 继续使用 Swift 与 AppKit，保持原生三栏界面，不引入 Electron。本版将 macOS 从基础控制界面扩展为与 Windows 共用 Core 管理契约的完整 Workbench。

- 工作区分组、搜索对话、近期记录、置顶、运行中和当前选中记录的稳定展示。
- 对话、任务和调用详情，以及重命名、标签、置顶、归档、回收站、恢复和永久删除。
- 对话与任务关联、当前任务切换、任务线程、终止/恢复对话和停止具体调用。
- 父子调用、根调用过滤、输出按需加载、下一段、重新从头读取、复制和导出。
- 中途插入编辑器、发送状态、回执、取消和有限重投。
- 审批记录、权限编辑、自定义权限开关和有效来源读取。
- Skill、插件、MCP、Core 服务、Tunnel、连接、更新、配置和日志管理。
- 浅色、深色、系统主题以及中英文界面，窗口大小和分栏位置可恢复。

　　活动 SSE 使用独立长连接会话，普通 REST 请求不会再用同一套短超时误伤长连接。活动流中断本身也不会直接把已经认证的 REST 快照标记成过期，而是重新读取 Core 状态。侧栏不再根据短暂 RPC 或单个调用状态显示闪动的“执行中”文字和运行调用数量，改为共享 Core 的近期活动标记，并继续独立显示待审批状态。

　　插入正文统一采用 8192 UTF-8 字节限制，并保留稳定 submission ID；权限编辑中的未提交选择不会被后台刷新覆盖；调用详情改变后会主动失效旧输出缓存。插件本地更新增加候选校验和来源变更确认，IPv6 loopback 地址构造和连接规则也进行了统一。

## 4. 共享 Workbench 管理接口与 Linux CLI

　　Windows、macOS、Android 和 CLI 现在围绕同一套 Workbench V1 管理接口工作。任务、对话、调用、审批、权限、插入和工作区状态继续由 Core 作为唯一权威，客户端不各自维护平行状态。

　　Linux 不新增桌面 UI，重点补齐 `agentdock` CLI 的在线管理能力。CLI 在保留原安装、更新、服务、Skill 和插件命令的同时，可以管理节点、工作区、任务、对话、调用、插入、审批、权限、能力和日志。

　　CLI 提供 `human`、`json` 和 `jsonl` 输出，直接使用后端分页与游标；活动、调用和对话跟随使用 SSE 并支持断线续接。错误使用稳定包络和退出码，部分成功会输出每一项实际结果。连接凭据优先从 token 文件或 OAuth 配置读取，不提供容易进入 Shell 历史的明文 `--token` 参数，并补齐 Bash、Zsh 和 Fish 补全。

## 5. 中途插入：收到补充后优先响应并继续原任务

　　1.1.8 在 1.1.7 已有插入队列、回执和有限重投基础上增加**注意协议**。Agent 收到活动中心投递的新补充后，需要在下一次业务操作前先给出一次用户可见的阶段总结，说明已经完成的工作、当前状态、新要求对后续步骤的影响，以及接下来立即执行的动作。

　　阶段总结之后继续同一任务，不因为收到插入、发送总结或接收回执而自动停止，也不要求用户再次发送“继续”。同一批消息可以集中总结，重复投递按 `insertion_id` 去重；接收回执只代表消息已经进入受信任处理链，不等于新增要求已经执行完成。

　　初始化提示、结构化附加、文本兼容输出和 `insertion_ack` 使用同一套行为要求，降低不同宿主投影方式下忽略用户中途补充的概率。

## 6. 自定义权限设置

　　权限系统新增明确的 **“启用自定义权限设置”** 开关。关闭时，已经保存的三层配置继续保留，但实际判定使用当前执行模式的基线值；重新启用后恢复使用原配置。

| 层级 | 作用 |
| --- | --- |
| Permission Profile | 文件系统、网络和工作区边界的硬上限 |
| Approval Policy | 决定操作按需审批、禁止审批或按类别细分 |
| Approval Reviewer | 选择用户审查或独立自动审查器 |

　　显式 deny 始终优先，Profile 不能被审批扩大，`never` 表示拒绝需要审批的动作。客户端直接读取 Core 返回的有效权限、配置来源和 revision，不在本地自行推导。

　　自定义权限只允许在全局或工作区配置；对话可以继承执行模式，但不能借此扩大权限。干净首次安装默认使用 full 执行模式，同时保持自定义权限开关关闭；升级、修复和已有策略不会被首次安装默认值覆盖。

## 7. 任务、对话与活动中心

　　本版把“最近有交互”和“仍在执行”分开处理。控制台“运行中”现在统计最近 120 秒内有有效交互的真实对话，并与侧栏近期活动标记共用同一半开时间窗口；命令结束后窗口自然到期，后台输出和 UI 刷新不会续期。总对话数独立统计，归档、回收站和已终止对话仍计入总数，但不计入近期运行。

　　Windows 与 macOS 不再用短暂 RPC 或调用执行状态显示闪动的“执行中”文字和运行调用数量，保留近期活动标记与待审批信息。旧 Core 缺少新汇总字段时显示状态不可用，不把未知值写成零。侧栏继续使用稳定导航身份，即使旧记录缺少、重复或暂时无法关联标准对话，也尽量保留可管理入口。

- 工作区分组、搜索、分页、置顶、选择和折叠状态更稳定。
- 运行中统计按对话去重，同一对话的并发根调用不会重复计数；未归属调用和永久删除对话不计入。
- 调用自身的 `running`、`pending` 和 `in_flight` 继续表达执行与审批状态，不改变停止能力和历史查询。
- 运行中、置顶和当前选中的重要对话不会简单被近期历史配额挤出。
- 合法未归属调用使用独立入口，不再与损坏对话混为一类。
- 搜索、分页或对象切换后，旧异步结果不能覆盖新的页面状态。
- 调用终态、退出码、错误和未知副作用状态保持真实，不会被后续观察改写成成功。
- 任务步骤、线程、完成条件和检查点通过共享管理接口向不同客户端统一暴露。

## 8. Agent、MCP、文件工具与插件

　　工具发现路径进一步区分 AgentDock 内置工具与动态 MCP。精确匹配内置工具时直接返回宿主权威定义；未指定 MCP 服务的宽泛搜索只读取现有目录缓存，不为了“找工具”启动所有无关服务。目录未知或过期时会明确返回下一步动作，而不会把“没有加载目录”解释成“没有这个能力”。

　　动态 MCP 错误会尽量保留原有结构化 code 和 details。工具失败恢复指引区分可安全重试、需要先查询副作用和必须恢复原任务的情况，减少 Agent 在结果未知时盲目重复调用。

　　文件搜索增加 `rg --no-config`、参数终止符和有界 stdout/stderr，避免本机 ripgrep 配置或以短横线开头的查询改变命令语义。带 include/exclude 过滤的搜索改由原生匹配器先限定文件范围，精确文件名可以直接定位目标，完整排除的子树可以提前剪枝。

　　插件 Git 来源进一步限制 selector 语法并增加参数边界，关闭 hooks、交互式凭据、递归子模块和自动 LFS 等隐式行为。插件更新时对候选包、来源变化和固定 revision 的处理更加明确。

## 9. 文件、归档、OAuth 与运行边界加固

- Skill、任务、状态和租约等文件通过固定根目录和安全路径边界读取，拒绝链接、特殊文件、非目录祖先和打开过程中的替换。
- ZIP/TAR 提取拒绝目录穿越、链接、特殊文件、重复目标、文件/目录冲突和尺寸溢出。
- 下载归档要求 HTTPS，并拒绝嵌入凭据、异常查询和不受控重定向。
- OAuth 授权只允许注册的精确回调，拒绝重复或未知参数及跨 Origin 端点。
- 浏览器输入通过 CDP 参数传递，不把用户输入拼进 JavaScript 源码。
- Android Termux 回执绑定 operation、request、nonce 与有效期，终态不能倒退为 running。
- 运行命令、文件工具和动态服务的输出继续保持有界，未知终态不会伪装成成功。
