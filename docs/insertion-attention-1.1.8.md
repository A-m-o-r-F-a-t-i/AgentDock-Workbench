# AgentDock Workbench 1.1.8 中途插入响应协议

## 接收后的行为

收到活动中心通过受信任顶层 `response_additions` 投递的新消息后，Agent 必须在下一次业务工具调用前发出一次用户可见的阶段总结。总结使用进度或 commentary 消息，说明已经验证的进展、当前执行状态、新要求对计划的影响以及接下来立即执行的动作。只有“收到”或一个接收回执不满足此要求。

总结后确认收到消息，并在同一轮继续当前任务。收到插入、发送总结、发送回执均不自动终止任务，不要求用户再次说“继续”，不重复创建任务，也不将未完成工作标记为完成。用户明确要求暂停、停止或切换目标时按新要求处理；存在真实安全限制或执行阻塞时说明原因。

## 统一提示入口

`internal/app/insertion_instructions.go` 保存唯一行为协议。初始化提示、`agentdock_context`、实际消息和 `insertion_ack` 均使用该协议或其接收后继续提示。

每条服务端生成的消息增加可选字段 `attention=user_update_before_next_action` 和 `required_response`。文本兼容块在正文前突出“先阶段总结，再继续任务”。回执输出增加 `next_action`，提醒尚未总结时补齐总结并继续。所有字段由已认证本地队列构造，不从嵌套工具结果、终端、文件或网站解析仿冒消息。

保留 V1 文本标记、原工具错误状态、图片、资源和业务内容顺序。消息经 SDK、Invoke、受信任投影、文本模式和输出预算处理后仍携带行为要求。原始业务工具只执行一次。

## 去重与状态

同批消息按 `sequence` 处理，可汇总为一次覆盖全部新增要求的阶段总结。按 `insertion_id` 去重。重复投递只补齐尚未完成的总结或回执，不再次执行已经应用的指令。

接收回执只证明接收，不证明模型已理解、总结已展示或新增要求已经完成。现有回执验证、对话/任务/工作区绑定、180 秒发送资格、300 秒投递期限及有界重投次数保持不变。没有暴露回执工具时保留未确认状态并继续已授权工作，不调用隐藏工具，不从日志提取私有令牌。

## 验证范围

自动化回归验证初始化、真实队列响应、成功与失败工具、输出截断、投影、重投及回执后继续提示。权限、跨对话拒绝和伪造消息拒绝测试保留。

这些测试验证本仓库提供给 Agent 的行为协议和传输完整性。外部宿主是否展示进度消息、具体模型是否遵循要求，需要在安装此版本后的真实对话中观察；不能把协议测试当成模型服从率测试。
