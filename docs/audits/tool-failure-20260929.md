## 3. Agent 设计与当前源码缺陷

### 3.1 不限定服务的发现会触发无关服务

　　手机有 62 次 mcp_tool_search 因 MCP_AUTH_REQUIRED 失败，查询没有指定服务。其中出现 task_manage、exec_command、mcp_tool_call 等内置工具名称。实际失败来自既有临时 artifact-fetch 服务缺少其声明的凭据。此前 SearchFiltered 遍历所有可见服务并调用 ensureTools，工具发现承担了初始化、凭据检查和远端可用性的全部失败面。

　　这是能力路由与连接生命周期耦合。模型把内置工具当动态 MCP 搜索会触发问题，工具层再把无关服务故障放大成整个搜索失败。修改后，精确内置名称从现有 Runtime 可用工具定义返回；未指定服务时只搜索缓存并列出未知/过期目录。用户需要某个远端能力时，才通过明确服务的 list/inspect 进入发现。显式服务仍执行原有鉴权、插件可用性和 Schema 检查。

### 3.2 已分类错误被重新包装

　　Windows 的 84 次 mcp_tool_inspect 失败落为 MCP_ERROR，摘要为 read MCP plugin availability。源码中 ensureAvailable 已经生成 PLUGIN_STATE_INVALID 等 ToolError，但 dynamicMCPToolError 只识别 MCP client.Error，随后将现有 ToolError 再包装为泛化错误。

　　这种信息丢失容易让 Agent 将插件状态错误当成普通可重试连接错误。本次保留已有 ToolError 的 code、details、retryable 和 cause，既不自动重试，也不弱化认证或审批失败。

### 3.3 搜索字符串进入 rg 选项位置

　　Windows 12 次搜索执行失败中，3 次原始查询以连字符开头，涉及负数坐标和 `-Werror`。源码直接把查询追加到 rg 参数，没有参数终止符。普通负数查询因此会进入命令选项解析。

　　本次为 rg 添加 `--` 参数终止符与 `--no-config`，并保留最多 4,096 字节的 stderr 和退出码。剩余 9 次 SEARCH_FAILED 没有足够的原始 stderr，不能全部判为同一种错误。其中多次针对浏览器 Profile 的固定文件名搜索，暴露了下一项扫描设计问题。

### 3.4 过滤条件不能约束实际扫描

　　现有 rg 分支先读取完整命令输出，再在 parseRGJSON 中应用 include_globs/exclude_globs。指定 Preferences 等固定文件并不能阻止访问同目录下的缓存、数据库或其他文件。原生 Go 分支也仅在文件层过滤，排除一个大型子树后仍会遍历其中的目录。手机记录中有 80 次 RESOURCE_LIMIT，主要是大目录搜索超时；具体每次由调用范围和运行环境各贡献多少，日志无法分离。

　　本次让带过滤条件的请求使用现有原生匹配器，保持 `*` 不跨目录、`**` 跨目录的契约。固定文件名直接定位，完整排除子树提前剪枝。隐藏路径、忽略规则和符号链接父目录的限制均保留。无过滤的 rg 分支设置 16 MiB 输出上限，溢出取消当前进程并返回 RESOURCE_LIMIT，原生扫描在内容循环中检查取消。

## 4. 已修复源码与旧运行环境

　　Windows 有 137 个失败根调用的最终摘要精确为 plugin directory changed during snapshot build，分布于 context、plugin_load、plugin_manage 和 read_file。另有插件注册表与可用性错误，但缺少内层详情的记录不能全部自动并入这 137 次。

　　最新主线 PR #24 已修复快照源身份与时钟耦合及相关重校验。PR #25 已增加上下文传输和命令会话/输入边界修复。审计时运行端仍是旧版，所以这里保留为已知旧运行故障，不重复修改已经修复的源文件，也不宣称已获得升级后的故障率下降数据。

　　7 次 SESSION_NOT_FOUND、28 次 WORKSPACE_PATH_OUTSIDE_ROOT、9 次 TASK_STATE_ERROR 及其他绑定错误显示 Agent 仍会复用无效状态或错误工作目录。它们包含调用方错误与旧运行时行为，必须结合具体调用来源判定。本分支不通过放宽工作区边界或复活失效会话来隐藏这些错误。

## 5. 外部故障、预期失败与证据不足

　　298 次 exec_command 失败包含：Node/Python 模块缺失、脚本和运行路径错误、Shell/PowerShell 语法错误、Git 凭据和引用问题、浏览器及 Bridge 未安装或断连、ADB 离线，以及编译、测试和故障注入返回非零退出。手机旧 Go 入口的段错误也属于工具链环境故障。根据非零退出本身，无法判断测试是否预期失败，更不能全部计为 AgentDock Core 缺陷。

　　18 次 MCP_ARGUMENT_INVALID 和 2 次 MCP_TOOL_NAME_INVALID 属于请求名称或参数不满足当前契约。需要重读目标服务 Schema，不能换名字连续猜测。图像工具的非图片输入和文件工具的二进制读取属于类型路由错误。PCB 对象过期、目标文档切换和写请求超时，应由领域插件查询回执与实际板面处理，超时不能自动等价为未执行。

　　Windows 的 5 次 CONVERSATION_TERMINATED 和 3 次 PLUGIN_SOURCE_CHANGE_CONFIRMATION_REQUIRED 是应尊重的停止/确认边界。取消和终止事件保留在执行结果中，但不作为应被消除的产品故障。明细没有可靠数据支撑一个排他、完整的“Agent 责任次数”，因此本报告不重复使用上一轮未充分核定的责任下限。

## 7. 后续实施边界

　　此次优先完成可在当前仓库稳定复现的 R1—R4。仍需分离处理的事项包括：提供覆盖至少 72 小时的可配置日志留存/归档策略；从活动索引导出真实根调用分母和预期负向测试标志；为领域 MCP 的副作用未知状态持续使用持久回执；在实际升级后重新采样，衡量新修复效果。它们没有通过本次代码修改全部实现。

　　完整去敏清单保存每条失败的设备、调用 ID、时间、工具、错误码、终态、退出码、父调用及源日志行位置。源码仓库仅提交汇总分析、修复计划、代码和合成测试，不提交个人日志正文、浏览器资料或任何认证值。生产 Core、插件启用状态、授权和设备保活配置保持不变。
